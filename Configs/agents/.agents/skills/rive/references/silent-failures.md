# What compiles clean and still does nothing

Ordered roughly by how often it wastes time. Everything here builds clean, verifies clean, and inspects clean. A zero exit code means no name was misspelled; it does not mean the file does what you asked.

Read this when something is wired correctly and still does nothing, and read the top few entries before starting anything non-trivial.

## The one that will bite you first

**A missing or misplaced clip mask renders the clipped shape invisibly.**

`ClippingShape` and its target each resolve in their own coordinate space. A mask shape left at the origin clips a shape positioned at `(200, 120)` down to nothing: the shape vanishes completely, `--verify` reports zero problems, and `inspect` shows a perfectly correct tree.

```xml
<!-- both at the same position, or the badge disappears -->
<Shape x="200" y="120" name="Badge">
    <Ellipse width="120" height="120"/>
    <Fill>...</Fill>
    <ClippingShape sourceId="0:20"/>
</Shape>
<Shape x="200" y="120" name="ClipMask" id="0:20">
    <Ellipse width="90" height="90"/>
</Shape>
```

This is the canonical case for the whole file: render, then look. No static check can see it.

## Silent, or too quiet to notice

### Missing asset file

An `<ImageAsset file="logo.png"/>` whose file is not on disk reports nothing at all. No error, no warning, no `problems` entry. `inspect` does not report the `file` attribute either.

To check for this, confirm every `file=` names a real path. This is the worst silent failure in the set because there is no automatic check.

### No `defaultStateMachineId`

`problems` warns about this (`no-default-state-machine`), so it is not silent, but the warning is easy to skim past and the consequences are larger than it suggests. Data binds are never applied and pointer input is never routed. An `ArtboardComponentList` with no bound state machine produces zero rows.

Animations are the exception: the runtime falls back to the first animation, so the file does not look dead and the missing state machine is easy to miss.

To check for this, read the `no-default-state-machine` warning rather than only checking that `problems` is non-empty.

### `ViewModelInstance.exports` defaults to false

An unexported instance is never written for the runtime at all. Your values are in the markup, the bind paths resolve, and the scene reads nothing.

To check for this, set `exports="true"` explicitly on every instance you bind.

### `undefined` units, which drop the value

Most dimensional properties take a companion `*UnitsValue`. Omitting the attribute is fine: it defaults to `points` and the value applies. But an explicit `unitsValue="undefined"` means the value is ignored, so `paddingLeft="16" paddingLeftUnitsValue="undefined"` lays out with no padding and nothing reports it.

This mainly arrives from generated or exported markup, since the default is the working one.

To check for this, search for `UnitsValue="undefined"` in a file you did not write by hand.

### A `LayoutComponentStyle` with no `styleId` link

Nesting the style element is not enough; the component must reference it. Every value is correct and nothing applies.

This is the one worth asserting mechanically.

```bash
rive inspect . --json | jq '[..|objects|select((.type//"")=="LayoutComponent" and .styleId==null)]|length'
```

Anything other than `0` is a box that will not lay out as written.

### A missing `LayoutComponentStyle` on an artboard

The CLI renders fine without it, so this looks harmless. The editor can never add one afterwards, so an artboard pushed without one is permanently broken for editors.

To check for this, look for the `artboard-without-style` warning in `problems`.

### Keyframe type mismatched to the property

`KeyFrameDouble` only writes `double`. Point one at a color, boolean, or reference and it never writes the value: the property holds still while the timeline runs.

To check for this, run `rive schema <Type>` for the property's type, then match it against the keyframe table in [animation.md](animation.md#keyframe-types-must-match-the-property).

### `cubic` or `elastic` with no nested interpolator

The easing type on its own does nothing. The nested interpolator child is what decides, not the enum.

A `cubic` keyframe needs a `CubicEaseInterpolator` or `CubicValueInterpolator` child, and `elastic` needs `ElasticInterpolator`.

### A listener with no `targetId`

The listener resolves to nothing and never fires, with no error.

### A state with no outgoing transition

The control works exactly once. Invisible to every static check; the three-screenshot comparison is the only way to catch it.

### `nameBased="true"` binds

The flag is accepted without complaint and the bind is inert, because the manifest it indexes is not generated by this toolchain. Worse, `problems` walks the path as ids whether the flag is set or not, so its verdict is meaningless in both directions.

The flag itself is visible in `inspect` even though the path is not.

```bash
rive inspect . --json | jq -c '[..|objects|select((.type//"")=="DataBindContext")
                               |select(((((.flags//0)/16)|floor)%2)==1)|.propertyKey]'
```

### Dangling bind paths

A `sourcePathIds` naming a property that does not exist loads, runs, and does nothing. Real editor-exported files contain this routinely.

To check for this, run `inspect`, which resolves paths and flags them as `unresolved-bind-path`. This is the one class `problems` is actually good at.

### Bind paths are absolute

`sourcePathIds` starts at a view model id and walks property ids. Relative paths are not supported in this format, so bind the deepest concrete property directly.

### `TextModifierGroup` values without their `modify*` flags

`rotation="0.5"` without `modifyRotation="true"` is a complete no-op. Every value on the group is inert until its flag is set.

Also: the default opacity behavior multiplies, so `opacity="0"` makes every glyph invisible rather than fading in. Use `invertOpacity="true"` when opacity is what you animate.

Range defaults leave a zero-width falloff, so glyphs pop rather than fade.

### `Feather` inside a `Fill`

The paint disappears entirely at every strength, with a clean build and empty `problems`. Feather strokes, not fills.

For a soft filled glow, use a `RadialGradient` whose outer stop has alpha `00`.

### Text with a broken three-way link

The style needs a `Fill` with a colour, the run needs `styleId`, and the style needs `fontAssetId`. Miss any one and the text renders as nothing, with no error and, unlike bind paths, not even a `problems` entry.

To check for this, render and look for the text.

### A missing font file

Rive ships no fonts and there is no system-font fallback. A missing or unloadable font is a hard stop, not a styling problem.

### Half-declared components

`NestedArtboard` pointing at an artboard not marked `isComponent="true"`, or missing its `ComponentAsset` entry, builds clean and inspects clean while being malformed. All four steps in [object-model.md](object-model.md#components) are required.

### `BlendAnimation1D` out of order

The runtime binary-searches the `value` list and does not validate it, so out-of-order entries silently blend the wrong pair. Weights also run 0–100, not 0–1.

### `points` and `cornerRadius` keyed with the wrong type

`Polygon.points` and `Polygon.cornerRadius` are bindable but not animatable. Keying them needs `KeyFrameUint`, and the result may not do what you expect.

### A keyed `SolidColor.colorValue` with `KeyFrameDouble`

Covered by the keyframe mismatch rule, but common enough to name: property key `37` is a `Color`, so it needs `KeyFrameColor`.

### Script inputs matched by name, silently

`ScriptInput*` names must match the script's field names exactly. Nothing checks them at build time.

### Script modules declared after their importer

`require('name')` only finds a module already registered, and registration follows document order. This type-checks clean and fails only at run time.

To check for this, run `--test` or render; the error appears in the console.

### Misspelled protocol hooks

The protocol table is matched by key name and unknown keys are dropped without complaint. Since every hook is optional, the type checker cannot help.

### `--data` silently overridden

A two-way bind overwrites the value you set, and the log still prints the assignment. Fix with `sourceToTargetRunsFirst="true"` on the `DataBindContext`.

## RML and format traps

### Draw order is front-to-back

The first sibling draws on top, the reverse of HTML and SVG. If a shape you added is invisible, suspect this first. Paint order inside one shape is the opposite: last-declared paints on top.

### `Component.flags` is editor state

`hidden`, `locked`, `guide`, and `opaque` are not read at runtime. `hidden="true"` renders identically to `hidden="false"`. Write the bits as their own boolean attributes, and do not expect them to hide anything.

### Rotation is radians

A full turn is `6.2831855`. Writing `360` spins fifty-seven times.

### `duration` means two different things

`LinearAnimation.duration` is frames (fps 60 by default). `StateTransition.duration` is milliseconds.

### `loopValue` defaults to `oneShot`

An animation with no `loopValue` runs once and holds its final frame. A continuous spin needs `loopValue="loop"`.

### `exitTimeIsPercetange` is misspelled upstream

The correct spelling is not accepted, so write the typo.

### A `Solo` with an unset `activeComponentId`

Shows nothing. Also note the keyframe for it needs `KeyFrameId` against property key `296`.

### Every listener under the pointer fires

Drawing over something does not block it unless the thing on top is explicitly `isTargetOpaque`, and a fully transparent fill is still hit-testable. Two listeners writing the same property will fight.

### `fill` on the cross axis of a `wrap` container

Collapses to zero.

### `--screenshot` always renders at `@1x`

A script that sizes its own canvas from `resize`'s `scale` looks perfect here and soft on a Retina display. This is the one defect class the render check cannot see by construction.

### `NestedSimpleAnimation.isPlaying` defaults to false

And `NestedRemapAnimation.time` is a fraction of the duration, not seconds.

### `NestedBool`/`NestedNumber`/`NestedTrigger` use `nestedValue`

Writing `value` is ignored.

### An artboard without `originX`/`originY`

Content authored relative to a shifted origin leaves the frame. Default is `0.5, 0.5`.

### `IKConstraint` outside a `Bone`

The whole file fails to import, and the error names no object.

### A `Mesh` that is not a child of an `Image`

Silently ignored. A missing `triangleIndexBytes`, or an index past the vertex count, takes the whole file down at load.

### `--artboard` with an unknown name

Silently falls back to the first artboard and exits 0. A green exit does not mean you captured the artboard you named.

### A capture with no `--advance`

You are looking at the pose before anything advanced. Start previews at `--advance=1`.

### Back-to-back clicks on the same target

A value a listener writes is not visible to the next listener until a frame has passed, so both can act on the pre-write value and a toggle latches on. Put a filler gesture between them. A `move` well away from the control is the cheapest.

## Things nothing checks

- An id that is set but points at nothing. `stateToId`, `animationId`, `inputId`, `styleId`, `targetId`, `viewModelPropertyId`, and `converterId` are never resolved. `problems` checks that a required reference is present, not that it resolves.
- A missing asset file. Nothing reports it.
- A keyframe whose type does not match its property.
- A modifier value with no matching `modify*` flag.
- Anything about appearance, such as size, overflow, spacing, or colour.
- Anything at all in a `.luau` script. `inspect` does not read Luau.
- Whether an artboard is bound to the view model a valid path names.

## Debugging procedure

When something does not work, in this order:

1. Run `rive . --verify --format=json` and read `problems`. Remember that `line`/`column` are zero-based there.
2. Run `rive inspect . --summary`. Is the object even there? Is the count what you expect?
3. Run `rive inspect . --json | jq`. Is it *wired*? Check `styleId`, `propertyKey`, and paths against the tables in the references.
4. Run `rive . --screenshot` and actually look at the image.
5. Run `rive . --data-dump=-`. Are the bound values arriving?
6. Run `rive . --test` for a script that type-checks but throws.

Step 4 is not optional and not a formality. Steps 1–3 routinely pass on a file that renders nothing at all.

### Assertions worth running

```bash
# every layout box still has its style linked
rive inspect . --json | jq '[..|objects|select((.type//"")=="LayoutComponent" and .styleId==null)]|length'

# object count, which must rise every pass
rive inspect . --json | jq '[..|objects]|length'

# problems
rive inspect . --json | jq '.problems'

# keyframes actually present, with their frames and values
rive inspect . --json | jq -c '[..|objects|select(.type?=="KeyedProperty")
  |{propertyKey, keys:[.children[]?|select((.type//"")|startswith("KeyFrame"))|{type,frame,value}]}]'
```

`rive inspect` also emits a `line` on each node, so a finding maps straight back to the source. The `//""` guard is not optional, because many nodes have no `type` and `startswith` on a null fails:

```bash
rive inspect . --json | jq -c '[..|objects|select((.line//0)==37)]'   # what is on line 37?
```
